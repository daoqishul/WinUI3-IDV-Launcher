# IDV 启动器 · WinUI 3 + 登录引擎

原生 **WinUI 3（Windows App SDK 1.8 + .NET 8）** 单窗口启动器。账号管理直接读取原版 `channels-v2.json` 的渠道账号，支持渠道服筛选和「登录账号」，并接入原版 IDV-Login 的 Python 登录引擎。

![账号管理](shots/winui/accounts-final.png)

## 账号管理

- **直接读取原版渠道账号**：名称、渠道、来源、上次登录、UUID，来自 `C:\ProgramData\idv-login\channels-v2.json`。
- **渠道服筛选**：顶部下拉选择「全部渠道 / 华为 / 哔哩哔哩 / 4399 / 应用宝…」，只显示该渠道账号。
- **登录账号**：每个账号行右侧按钮，按该账号所属渠道登录：
  1. 把该 UUID 写入 `auto-h55`；
  2. 停止并重启登录引擎，让新默认账号生效；
  3. 通过引擎托管启动游戏，由引擎按账号渠道完成登录/切服。
  - 游戏正在运行时不能直接切换，请先关闭游戏。
- **设为默认**：点击星标，写入 `auto-h55`，下次登录使用。
- **添加渠道账号**：点按钮选择渠道服，直接打开该渠道的登录网页；账号写入原版 `channels-v2.json`，不再打开原版账号管理窗口。
- **收藏账号直接登录**：在账号管理点小星星设为收藏后，首页会自动选中该账号；启动游戏时直接登录该账号，不显示内置登录窗口。没有收藏时，首页不自动选择，可手动选号后直接登录。
- **改名 / 删除**：行尾菜单原生完成；引擎运行时走本地引擎 API，未运行时直接原子修改 `channels-v2.json`（带备份和管理员 ACL）。
- 搜索账号 / 渠道 / UUID；空状态引导；默认账号与渠道颜色徽标。

> 账号管理全程在 WinUI 窗口内完成；原版账号管理界面不再打开。

## 界面

- 重新构建的账号页：卡片行、渠道徽标、醒目的「登录账号」按钮、渠道服筛选。
- **个性化**：颜色模式（跟随系统 / 深色 / 浅色）、全局云母 / 全局亚克力 / 纯色、圆角 / 直角。
- **窗口**：默认记住上次窗口大小/位置；关闭“记住窗口大小”后每次启动固定 1268×690。
- **小托盘**：设置中开启后，关闭窗口会隐藏到系统托盘，双击显示，右键退出。
- 中性页面底色、系统卡片/描边、Fluent 控件。
- 左侧「解帧」页：解帧开关 + 目标帧率（上限 500），调用 `Tools\解帧.exe`。
- 解帧工具改为创建隐藏的真实控制台并注入键盘输入，修复 `ReadConsole` 型工具在重定向 stdio 下卡住/超时的问题。
- 修复解帧实际输入：工具显示的是 `PID-ID: 1`，要输入的是列表 ID（1），不是游戏 PID；控制台输出改为 Unicode 读取，避免读不到提示。
- 设置移到底部左侧；顶部高度、页面留白和卡片间距收紧。
- 主窗口不强制置顶，也移除了启动后的延迟抢焦点；关闭时安全清理引擎并停止页面异步回调。
- 关闭窗口时先立即隐藏界面，再在后台停止登录服务并清理网络配置，避免等待引擎退出造成“点了关闭不消失”。
- 修复手动切换深色/浅色时 `Microsoft.UI.Xaml.dll` 崩溃：主题切换延后到下拉框关闭后执行，背景材质只在材质变化时重建，圆角不再改全局控件资源。
- 设置内新增「下载游戏」，打开 `wiki.biligame.com/dwrg` 的 PC 互通版页面。
- 设置 → 赞助下拉菜单显示赞助码，标题为“想要更新快一点？来赞助吧！”。
- 软件图标改为 `777.png`：仅用于设置「关于」和 exe，不放到左上角。
- 首页封面使用 `51.jpg`，启动按钮贴近右下角；账号选择是独立下拉区域。
- 首页账号区上方显示登录服务状态；未启动/启动失败时可点「启动登录服务」手动重试。
- 侧边栏可折叠并记忆状态；窗口大小/位置默认保留上次设置。

## 云存档

- 使用原版 IDV-Login 的加密云同步接口，不打开原版界面。
- 支持主密钥生成、同意存储说明、上传本地、下载云端、双向同步、自动同步、删除云端。
- 主密钥至少 12 位且包含 3 类字符；启动器默认不保存主密钥。
- 下载会覆盖本地账号记录，操作前请确认。

## 游戏设置

- 设置页顶部新增「游戏设置」，直接读取游戏目录下的 `Documents\setting_data.json`。
- 支持画质预设（流畅/均衡/高清）、全屏/窗口化、高帧率。
- 需要先关闭游戏再应用，下次启动游戏生效；修改前保留 `.idvlauncher.bak` 备份。
- 原版设置文件没有独立的窗口宽高字段，窗口大小仍由游戏窗口和系统记忆控制。
- 「编辑键位」是 WinUI3 原生页面：显示当前按键配置文件路径，支持自动查询；按通用/求生者/监管者/加页手记/其他模式分类，点击按键后按新按键、Enter 保存；不调用外部 `dwrg-key-rust.exe`。

## 持久化与性能

- 设置使用原子写入并保留 `.bak`；主题、背景、圆角、侧边栏、窗口大小/位置和最后页面都会保留。
- 引擎、游戏进程检测改为轻量路径，首页定时器不再全进程扫描。
- 页面切换取消入场动画，背景图限制解码宽度，启动器体积进一步缩小。
- 解帧页进程检测改为后台执行，并只查已知游戏进程名，避免点击「解帧」时卡顿。
- 「启动后最小化」默认关闭。

## 免责声明

- 第一次打开软件会弹出免责声明：同意继续，不同意直接退出。
- 设置页保留「查看完整免责声明」入口。
- 第一次进入「解帧」页需要填写“我同意并且后果自负封号由我来承担”；可点「一键填写同意」自动写入，再点同意进入；不同意会返回主页。
- 解帧页常驻红色警告：“封号后果自负本人概不负责！”

## 登录引擎

- 启动器打开后**自动、隐藏启动**登录服务，用户不需要手动点“启动引擎”；首页仍保留手动启动入口以防自动启动失败。
- 启动等待从每 800ms 检查一次改为 250ms，并同时探测本地 HTTPS 健康接口，通常能更快进入已就绪状态。
- 设置页不再显示引擎目录、代理端口或启动/停止按钮；由程序自动检测和管理。
- 代理模式：兼容（DNS 劫持，推荐）/ 进程 / 全局。
- 默认渠道账号、登录延迟、登录后自动关闭引擎。
- 「游戏与启动」只保留只读游戏路径；不再显示原版引擎账号列表或启动按钮。
- 首页公告直接抓取官方 `id5.163.com/news`，网络失败时回退本地缓存。
- 停止或退出启动器时发送 Ctrl+C，让引擎清理 NRPT / 代理 / hosts。

### 新版发烧平台绑定

原版没有直接修改游戏文件或注入 DLL。源码里真正的处理在：

- `gamemgr.py` 的 `Game.start()`：判断 `should_use_fever_bridge()`；
- 命中时调用 `fever_bridge.py` 的 `FeverBridge.activate()`，由引擎托管 mpay / 网易发烧平台 IPC，向游戏提供平台登录票据；
- 游戏因此走**内置登录界面**，而不是强制要求真实发烧平台。

之前的启动器直接 `Process.Start("dwrg.exe")`，绕过了 `Game.start()`，所以 FeverBridge 没有激活，新版游戏就卡在绑定提示。

现在「启动游戏」和「登录账号」都通过引擎的 `/_idv-login/start-game`（或命名管道 `start`）启动，由引擎执行 `Game.start()`，FeverBridge 会自动激活，不再直接拉起 `dwrg.exe`。

首次使用：管理员运行 → 阅读并同意免责声明 → 在设置确认游戏路径 → 「账号管理」→「添加渠道账号」→ 选渠道服，在渠道网页完成登录 → 选账号 → 登录账号。登录服务会自动启动。

## 风险与边界

- 原版引擎会修改 **hosts / NRPT / 证书 / 代理 / 本地端口**，并以管理员运行；正常停止/退出会请求清理，强杀可能残留。
- 本启动器不打包 Python 引擎，只负责启动/停止、读取账号列表、写入 `config.json` 的公开配置项（`auto-h55`、代理模式、延迟、自动关闭、游戏路径）。
- 原生添加/改名/删除在引擎运行时走本地 HTTPS API；需要引擎处于兼容模式（默认）。引擎未运行时，改名/删除会直接原子修改 `channels-v2.json`。
- 「登录账号」采用「重启引擎 + 启动游戏」的方式应用渠道；不是原版游戏内即时切换。游戏运行中请先关闭再切换。
- 添加账号时选择渠道后，渠道网页由引擎打开；WinUI 不再弹额外提示。
- 渠道登录本身仍由引擎完成；部分渠道（如 4399 网页登录）会弹出渠道自己的登录窗口，这是渠道登录流程，不是原版账号管理器。
- 「登录账号」本身会重启引擎并重新走该账号的渠道登录；若渠道凭据已过期，可再添加一次该渠道账号。
- 请只使用自己的账号，遵守游戏用户协议；本项目与网易 / 第五人格官方无关。

## 构建

```powershell
# Release（嵌入 requireAdministrator 清单）到 dist
powershell -ExecutionPolicy Bypass -File .\build.ps1

# 同时生成 zip
powershell -ExecutionPolicy Bypass -File .\build.ps1 -Package
```

- Release 使用 `app.admin.manifest`（`requireAdministrator`），发布目录约 37 MB。
- Debug 使用 `app.manifest`（`asInvoker`），便于不弹 UAC 调 UI；此时账号页会提示需要管理员并显示本地记录。
- framework-dependent：目标机需要 .NET 8 Desktop Runtime 和 Windows App Runtime 1.8。
- 调试参数：`--page=home|accounts|settings|engine`。
